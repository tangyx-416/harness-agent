## Work Completed

### 1. URL Redirection Vulnerability Discovery and Fix

**Vulnerability Found:**
Git config rules (`url.*.insteadOf`, `url.*.pushInsteadOf`, `remote.*.pushurl`) can silently redirect an approved GitHub push to an attacker-controlled host, even when using explicit `git push <url>`.

**Root Cause:**
Original `policy.py` step 7 used `git remote get-url origin` which **already applies** `insteadOf` rewriting. So the `approved_remote_url` stored the rewritten evil URL, and prefix-based detection had nothing to catch.

**Fix Implemented:**
Added `_reject_url_redirection()` in `policy.py` (step 8b) that compares:
- Raw configured URL: `git config --get remote.<name>.url`
- Effective push URL: `git remote get-url --push <name>`

Any difference triggers rejection at prepare time. This is ground truth for where Git will actually push.
