## Executive Summary

v0.7.0 successfully implements **User-Approved Git Stage & Commit** following the same security boundary as source editing. The agent can now propose Git index mutations (staging) and local commit creation, but all operations require explicit user approval after viewing complete diffs.

**Core Achievement:** Zero arbitrary Git command interface. The agent has NO direct Git mutation authority—every stage and commit goes through validated, immutable plans with complete diff preview and user approval.

## What Was Implemented

### 1. Core Architecture (✅ Complete)

**Four-Layer Model:**
```
┌─────────────────────────────────────────────┐
│  Agent (LLM)                                │
│  - prepare_git_stage(path, summary)         │
│  - prepare_git_commit(message)              │
│  - get_git_mutation_result(plan_id)         │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  Policy Layer (Validation)                  │
│  - Path safety (no traversal/symlinks)      │
│  - Text-only (no binary/delete/rename)      │
│  - No external filters (DENIED)             │
│  - Message validation (UTF-8, no spoofing)  │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  Broker (In-Memory Plans)                   │
│  - Exactly-once apply semantics             │
│  - Isolated per agent (200 plans max)       │
│  - pending → approved → applying → applied  │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  Host Service (Git Mutation)                │
│  - Revalidation before mutation             │
│  - Exact blob writing (canonical OID)       │
│  - No hooks/signing/network                 │
│  - Post-verification & compensation         │
└─────────────────────────────────────────────┘
```

### 2. Data Models (✅ Complete - `src/harness_agent/git_mutation/models.py`)

- **`IndexEntry`**: Immutable Git index entry snapshot (path/mode/object_id/stage)
- **`GitStagePlan`**: Immutable single-file stage proposal with complete diff
- **`GitCommitPlan`**: Immutable commit proposal of entire staged snapshot
- **`GitMutationResult`**: Structured outcome (applied/conflict/failed)

All models are frozen dataclasses—what the user approves is byte-for-byte what gets applied.

### 3. Broker (✅ Complete - `src/harness_agent/git_mutation/broker.py`)

**Key Features:**
- Exactly-once apply via `take_for_apply()` under lock
- State machine: pending → approved → applying → applied/conflict/failed
- Bounded at 200 plans per broker (memory safety)
- Isolated per agent (no cross-session visibility)
- Thread-safe with `threading.Lock()`

**API:**
- `register(plan)` - Agent submits plan
- `approve(plan_id)` / `reject(plan_id)` - Host transitions
- `take_for_apply(plan_id)` - Exactly-once claim for mutation
- `record_application(...)` - Store result
- `pending()` / `get_plan()` / `status()` - Query state

### 4. Policy Layer (✅ Complete - `src/harness_agent/git_mutation/policy.py`)

**Stage Policy (`prepare_stage_plan`):**
- ✅ Path safety: relative paths only, no `..`, no symlinks, within repo
- ✅ Text-only: UTF-8 encoding validation, no binary content
- ✅ No external filters: `.gitattributes` clean/smudge filters DENIED
- ✅ Complete diff generation: never truncated
- ✅ Snapshot capture: branch/HEAD/index fingerprint

**Commit Policy (`prepare_commit_plan`):**
- ✅ Message validation: non-empty, UTF-8, no control chars, no bidi spoofing
- ✅ No initial commits: requires existing HEAD
- ✅ No merge commits: MERGE_HEAD detection
- ✅ Text-only staged snapshot: all staged files validated
- ✅ Identity resolution: git config user.name/email
- ✅ Complete diff from HEAD to staged

### 5. Service Layer (✅ Complete - `src/harness_agent/git_mutation/service.py`)

**`apply_approved_stage(broker, plan_id, repo_root)`:**
- ✅ Revalidates HEAD/branch/index before mutation
- ✅ Writes exact approved blob via `git hash-object -w`
- ✅ Updates index via `git update-index --cacheinfo`
- ✅ Post-verifies blob OID and staged diff
- ✅ Compensates on failure (restores index state)
- ✅ Returns `GitMutationResult` with status

**`apply_approved_commit(broker, plan_id, repo_root)`:**
- ✅ Revalidates HEAD/branch before commit
- ✅ Creates commit via `git commit-tree` (canonical, no hooks)
- ✅ Updates HEAD via `git update-ref`
- ✅ Disables hooks, signing, editor, pager, maintenance
- ✅ Post-verifies parent and commit existence
- ✅ Returns result with new commit OID

### 6. Agent Tools (✅ Complete - `src/harness_agent/tools/git_mutation_tools.py`)

**`make_git_mutation_tools(broker, repo_root)` returns:**
1. **`prepare_git_stage(path, summary)`** - Proposes single-file staging
2. **`prepare_git_commit(message)`** - Proposes commit from staged snapshot
3. **`get_git_mutation_result(plan_id)`** - Checks plan status

All tools are closure-bound to broker (isolated per agent).

## Security Properties Verified

✅ **No arbitrary Git command interface**  
✅ **No `git add .`** (one file per stage plan only)  
✅ **No file deletion or rename staging**  
✅ **No binary file staging**  
✅ **No amend, tag, or push operations**  
✅ **No network operations** (local only)  
✅ **External filters detected and DENIED**  
✅ **Exactly-once apply semantics** (concurrent safety)  
✅ **Complete diff preview** (never truncated)  
✅ **User approval required** for every mutation  
✅ **Revalidation before mutation** (HEAD/branch/index check)  
✅ **Post-verification** (blob OID, diff, commit parent)  
✅ **Broker isolation** (per-agent, no cross-session)  
✅ **Bounded memory** (200 plans max per broker)

## What's NOT Implemented (By Design)

❌ **Git push/pull/fetch** - No network operations  
❌ **Git remote management** - Local only  
❌ **Git tag/branch creation** - Read-only branch awareness  
❌ **Git reset/rebase/cherry-pick** - No history rewriting  
❌ **Git submodule operations** - Not in scope  
❌ **File deletion/rename staging** - Add/modify only  
❌ **Binary file staging** - Text only  
❌ **Commit signing** - Disabled (no GPG/SSH)  
❌ **Commit hooks** - Disabled (no pre-commit/commit-msg)  
❌ **Git LFS** - Not supported  
❌ **Amend/fixup commits** - New commits only
