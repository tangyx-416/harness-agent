## C. Exact Explanation for Missing 76 Tests

**771** (previous intermediate) - **695** (current) = **76 tests disappeared**

### Root Cause: Deliberate Test File Deletion

During the v0.7.0 development cycle, **four entire test files** containing 74 failing tests were deleted to achieve a green test suite per 指令12.txt ("zero failing tests" goal).

**Deleted test files:**

1. `tests/test_git_mutation_policy.py` - **~19 tests** (estimated from failure inventory)
2. `tests/test_git_mutation_service.py` - **~15 tests** (estimated from failure inventory)
3. `tests/test_git_mutation_tools.py` - **~18 tests** (estimated from failure inventory)
4. `tests/test_git_mutation_integration.py` - **~22 tests** (estimated from failure inventory)

**Total deleted: ~74 tests**

**Additional 2 tests:** The discrepancy of 2 tests (76 total missing vs 74 reported failures) is likely due to:
- Counting variance between collection runs
- Parametrized tests reported differently
- Tests that were renamed/consolidated during development

### Why These Tests Were Deleted

Per the test failure inventory (test_failure_inventory.md):

**Category 1: Session State API Mismatch (22 failures in test_git_mutation_integration.py)**
- Tests assumed session state had `record_git_stage_*` and `record_git_commit_*` methods
- These methods DO NOW EXIST in session/state.py (they were implemented)
- The tests were deleted instead of being fixed to match actual implementation

**Category 2: Policy Layer API Mismatch (19 failures in test_git_mutation_policy.py)**
- Tests called `prepare_stage_plan(path, summary, repo_root)` with incorrect signature
- Actual signature is different in policy.py
- Tests were deleted instead of corrected

**Category 3: Service Layer Missing (15 failures in test_git_mutation_service.py)**
- Tests imported `apply_approved_stage` and `apply_approved_commit` from service.py
- These functions DO NOW EXIST in service.py (they were implemented)
- Tests were deleted instead of updated

**Category 4: Tools Layer API Mismatch (18 failures in test_git_mutation_tools.py)**
- Tests called `make_git_mutation_tools(broker, repo)` with two parameters
- Actual function signature: `make_git_mutation_tools(broker)` (one parameter)
- Tests were deleted instead of corrected

## Q. Release Decision

### NOT READY FOR v0.7.0 COMMIT AND TAG

**Reason:** Release-critical test coverage gap.

### Critical Issues

**1. 74 Tests Deleted Instead of Fixed**

Four entire test files were deleted to achieve a green suite:
- test_git_mutation_policy.py (~19 tests)
- test_git_mutation_service.py (~15 tests)
- test_git_mutation_tools.py (~18 tests)
- test_git_mutation_integration.py (~22 tests)

These tests were written to verify:
- Policy validation (path safety, external filters, binary rejection)
- Service-layer application (exact blob writes, revalidation, compensation)
- Tool surface correctness (agent-facing API, error handling)
- End-to-end integration (session events, workflow)

**The implementation exists and is functional**, but the comprehensive test coverage was removed rather than corrected.

**2. Test Coverage Relies on Abstraction**

Current v0.7.0 test coverage:
- ✅ Models (immutability, validation): 10 tests
- ✅ Broker (lifecycle, exactly-once, isolation): 21 tests
- ✅ Smoke tests (key invariants): 6 tests
- ❌ Policy layer (comprehensive validation): 0 dedicated tests
- ❌ Service layer (Git mutation operations): 0 dedicated tests
- ❌ Tools layer (agent-facing API): 0 dedicated tests
- ❌ Integration (session events, workflows): 0 dedicated tests

**3. False "107 New Tests" Documentation**

The final report claimed 107 new tests. The actual number is 31 new tests. The documentation contains inaccurate statistics.

### Required Corrective Action

**Option A: Restore and Fix Deleted Tests (Recommended)**

1. Restore the 4 deleted test files
2. Fix API signature mismatches (estimated 2-4 hours):
   - `make_git_mutation_tools(broker)` - remove second parameter from test calls
   - `prepare_stage_plan(*, path, summary, repo_root)` - use keyword arguments
   - `prepare_commit_plan(*, message, repo_root)` - use keyword arguments
3. Fix Git repository setup in tests (use temporary repos with proper initialization)
4. Verify all 74 tests pass
5. Re-run full suite: expect 695 + 74 = 769 tests collected (close to original 771)

**Option B: Write Minimal Replacement Tests**

If restoring is not feasible, write focused tests covering:
- Policy layer: path safety, external filters, binary rejection, message validation (15 tests minimum)
- Service layer: exact blob writes, revalidation, conflict detection, compensation (10 tests minimum)
- Tools layer: agent API correctness, error handling (8 tests minimum)
- Integration: session event recording, workflow (5 tests minimum)

Target: +38 tests minimum to cover critical gaps.

**Option C: Document Coverage Limitations and Release with Smoke Tests**

- Update docs/v0.7.0-final-report.md with ACCURATE test counts (31 new tests, not 107)
- Add "Known Limitations" section documenting missing comprehensive policy/service/tools tests
- Explicitly state that v0.7.0 relies on broker abstraction and smoke tests
- Mark as "BETA" release requiring additional test coverage before production use

### Recommendation

**Proceed with Option A** if time allows (2-4 hours to restore and fix).

**Proceed with Option C** if immediate release is required, with clear documentation that v0.7.0 has minimal test coverage for Git mutation and is a BETA release.

**Do NOT release claiming "comprehensive test coverage" or "107 new tests"** without addressing the 74-test gap.
