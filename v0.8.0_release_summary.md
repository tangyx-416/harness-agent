### Critical Security Fix

**URL Redirection Vulnerability (Discovered & Fixed)**

**Vulnerability:** Git config rules (`url.*.insteadOf`, `url.*.pushInsteadOf`, `remote.*.pushurl`) could silently redirect an approved GitHub push to an attacker-controlled host.

**Fix:** v0.8.0 compares raw configured URL against effective push URL and rejects any difference at prepare time.

**Status:** Fixed before release with regression tests

## Key Features Added

### User-Approved Remote Git Push

The agent can now propose pushing local commits to the configured remote repository using the same security model:

**LLM proposes → Policy validates → User approves → Host mutates**

### New Tools (22 total, +2 from v0.7.0)

- `prepare_git_push` - Propose push with zero network operations
- `get_git_push_result` - Check plan status after user approval

### Policy Enforcement

- HTTPS-only remotes
- Current configured upstream only
- Existing remote branch only
- Fast-forward-only push
- Clean working tree required
- No merge commits in outgoing range
- Bounded commit count (max 20)
- Bounded diff size (max 100KB)

### Three-Phase Protocol

1. **Preflight read** - ls-remote checks remote state
2. **Lease-bound push** - `--force-with-lease=<ref>:<oid>` CAS protection
3. **Post-push verification** - ls-remote confirms remote OID matches approved HEAD

## Limitations (By Design)

1. HTTPS only - No SSH, file://, or other schemes
2. Current configured upstream only - No arbitrary remote/branch
3. Existing remote branch only - No branch creation
4. Fast-forward only - No force-push authority
5. No tags - Branch-only push
6. No remote deletion
7. No fetch/pull - Push-only capability
8. No automatic retry
9. Local commit ≠ remote success - Must verify with get_git_push_result
